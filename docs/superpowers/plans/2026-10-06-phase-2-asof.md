# Phase 2: `as_of` Layer + Leakage Tests Implementation Plan

> **For agentic workers:** Implement task-by-task (one implementer per task, then review). Checkbox (`- [ ]`) steps. TDD: failing tests first.

**Goal:** A single, enforced read path for everything downstream of `data/`: `DataStore(data_dir).as_of(deadline)` returns a view that only exposes rows whose `available_at` is strictly before the deadline. A first set of baseline feature builders that Phase 3 needs reads only through it. A corrupt-the-future harness proves it: randomising (and adding) every row at or after a deadline leaves every feature byte-identical. Phase 2 "done when": the corrupt-the-future test passes (in CI on synthetic data, and locally on the real data).

**Spec:** `docs/PLAN.md` §3 (tables), §4 (leakage), §5 (backtester needs), §9. Built on Phase 1b's tables (`src/fplopt/build/`).

**Branch:** `phase-2-asof` (exists).

**Holdout:** 2025/26 stays untouched: no outcome statistics; leakage checks on real data use deadlines from 2016/17–2024/25 and 2026/27 only.

## Semantics (decided here; record in PLAN §4 in Task 0)

- `as_of(deadline)` keeps rows with `available_at < deadline` (strict). A row available exactly at the deadline is for the next decision.
- **"Known by the deadline"** rows (state at deadline t that was fixed beforehand: price at t, registration/club at t) get `available_at = deadline_t − 1 h` (`KNOWN_BEFORE_DEADLINE = 1h`). FPL price changes happen overnight, so the price at deadline t is fixed hours before.
- **"Final at the deadline"** rows (state that keeps moving until the deadline: ownership after GW t transfers, GW t transfer totals) get `available_at = deadline_t` → first visible at deadline t+1 (#6).
- **Schedules** (fixture list, GW deadlines) are known in advance: `available_at = schedule publication`, approximated as **1 June of the season's start year, 00:00 UTC** (FPL publishes mid-June). Historically only the *final* schedule exists (rescheduled blanks/doubles leak — accepted, PLAN §3); from 2026-10-05 the as-of schedule comes from `fixture_snapshot`.
- Results/outcomes keep their Phase 1b `available_at` (GW lockdown).
- Snapshot tables (`player_snapshot`, `fixture_snapshot`, `odds_snapshot`) are read via "latest snapshot before the deadline".

### Task 1: Table changes and new tables

**Files:** `src/fplopt/build/tables.py`, `fixtures.py`, `players.py`, `__init__.py` (registry/ORDER), tests.

1. `tables.py`: `TableSpec(name, kind, key: tuple[str, ...], snapshot_col: str | None = None)`; `TABLES: dict[str, TableSpec]` covering **every** table the build writes (incl. `understat_player_match`, `understat_map`). Kinds: `team_dim, player_dim, understat_map` static; `schedule, gameweek` schedule; `player_snapshot, fixture_snapshot, odds_snapshot` snapshot (`snapshot_col` = `snapshot_at`); the rest event. Test: the set of Parquet files a synthetic `build all` writes equals `TABLES`' keys, and each table's key is unique.
2. `gameweek`: `available_at` = publication time (1 Jun of the season's start year UTC). `event_time` stays the deadline. Update consumers/tests (e.g. `player_season` uses `deadline_time`, not `available_at`).
3. `schedule` (new, schedule kind): one row per fixture from `fixture` — `fixture_key, season, gw, gw_index, kickoff_time, home_team_key, away_team_key, schedule_source ('final'), event_time (kickoff, or the unscheduled sentinel), available_at (publication)`. No result columns. `fixture` itself is unchanged (results; lockdown availability).
4. `fixture_snapshot` (new, snapshot kind): every `raw/fpl/fixtures/*.json.gz` — `snapshot_at, season, fixture_key, gw (nullable), kickoff_time (nullable), home_team_key, away_team_key, finished_provisional/started flags if useful (no scores), event_time = available_at = snapshot_at`. Team ids → codes via the bootstrap of the same season closest at/before the snapshot (ids are stable within a season). Season from kickoff times / matching bootstrap (reuse Phase 1b per-season helpers). Validation: unique `(snapshot_at, fixture_key)`; each snapshot has 380 fixtures.
5. `player_season.available_at` → `deadline_of_first_row − 1h` (registration known before that deadline).
6. `player_gw` (new, event): one row per (player_key, season, gw) the player was registered for (from vaastav merged_gw rows, all minutes incl. 0; and 2026-27 element-summary history rows): `player_key, season, gw, team_key (the team of that GW's fixture), element_type (players_raw / bootstrap; FPL positions are fixed within a season), value (tenths of £m), event_time = deadline_t, available_at = deadline_t − 1h`. Doubles: one row per GW (values identical across the two fixture rows — verify; fail if not). Blank GWs have no row (no fixture) — fine.
7. `player_gw_ownership` (new, event): `player_key, season, gw, selected, transfers_in, transfers_out, event_time = available_at = deadline_t`. Same sources/dedup.
8. Validation: `player_gw` / `player_gw_ownership` unique on (player_key, season, gw); gw ⊂ gameweek; value > 0.

Tests: gameweek publication time; schedule has no result columns; fixture_snapshot from two synthetic snapshots (one rescheduled kickoff); player_gw dedup across a double; ownership availability; TABLES coverage test.

Commit(s): `feat(build): table metadata registry; schedule, fixture_snapshot, player_gw tables; schedule availability`.

### Task 2: `DataStore` / `AsOfView`

**File:** `src/fplopt/features/store.py`, `tests/test_features_store.py`.

```python
class DataStore:
    """Loads data/ tables once (lazily, selected columns) and hands out deadline views.
    The only place in fplopt.features that reads files."""
    def __init__(self, data_dir: Path, tables: Mapping[str, pd.DataFrame] | None = None): ...
    def as_of(self, deadline: pd.Timestamp) -> AsOfView: ...

class AsOfView:
    deadline: pd.Timestamp          # tz-aware UTC; naive → ValueError
    def table(self, name, columns=None) -> pd.DataFrame        # rows with available_at < deadline
    def latest(self, name, by: Sequence[str], columns=None) -> pd.DataFrame
        # snapshot tables only: rows of the newest snapshot_at < deadline (per `by` group,
        # e.g. latest per element across sources: prefer 'fpl' over 'fplcache' at equal time)
    def schedule(self, season: int) -> pd.DataFrame
        # as-of fixture list for `season`: newest fixture_snapshot < deadline for that season
        # if any (schedule_source='snapshot'), else the `schedule` table ('final')
    def gameweek_for_deadline(self) -> tuple[int, int]   # (season, gw) whose deadline == deadline
```
- Unknown table → `KeyError` listing names from `TABLES`.
- Returned frames are copies (callers can't mutate the store); `available_at` filtering uses the column, never `event_time`.
- Performance: tables are loaded once per `DataStore`; `player_snapshot` is large (5.7M rows): load only requested columns, keep it sorted by `snapshot_at`, and find the latest snapshot time with `searchsorted` (no full scans per deadline). Target: a `latest("player_snapshot", ...)` call < 0.5 s on real data after the first load.
- `DataStore(tables=...)` accepts in-memory frames (tests and the leak harness).

Tests: strict `<`; naive deadline rejected; unknown table; `latest` picks the newest snapshot before the deadline and ignores later ones; `schedule` switches from final to snapshot once a snapshot exists for the season; copies are independent.

Commit: `feat(features): DataStore and as-of views`.

### Task 3: Baseline feature builders

**Files:** `src/fplopt/features/baseline.py`, `src/fplopt/features/__init__.py`, `tests/test_features_baseline.py`.

Each builder: `(view: AsOfView) -> pd.DataFrame`, deterministic (sorted by key, stable dtypes), reads only through `view`. Target GW = the GW whose deadline equals `view.deadline` (`view.gameweek_for_deadline()`).
1. `player_pool` — players available to pick for the target GW: from `latest("player_snapshot")` when a snapshot exists in that season before the deadline; else from `player_gw` rows for the target GW (available deadline − 1h) unioned with the newest earlier `player_gw` row per player that season (blank GW). Columns: `player_key, element_type, team_key, price (tenths), source ('snapshot'|'player_gw')`.
2. `availability` — from the latest snapshot: `status, chance_of_playing_next_round, news_added`; nulls where no snapshot (pre-2021).
3. `ep_next` — latest snapshot `ep_next` (null pre-2021).
4. `recent_form` — per player from `player_match` rows of the current season visible as of the deadline: last 5 and season-to-date sums of `minutes, starts, total_points, goals_scored, assists, us_npxg, us_xa, fpl_xg, fpl_xa`, appearances, and per-90 rates (null when minutes = 0).
5. `upcoming_fixtures` — for the target GW and the next 5 GWs (by `gw_index`): per team and GW, list of opponents/home flags and fixture count (0 = blank, 2 = double) from `view.schedule(season)`.
6. `team_strength` — latest Elo `rating_after` per team before the deadline (`team_rating`), and for each upcoming fixture in the target GW the newest pre-deadline `odds_snapshot` h2h (prefer `avg` from football-data, else the median across Odds API bookmakers of the newest snapshot) converted to overround-normalised probabilities.
- `FEATURES = {name: builder}`; `compute_features(view) -> dict[str, pd.DataFrame]`.

Tests: on a synthetic world (reuse `tests/synthetic_raw.World` + build all) at a mid-season deadline: pool size and sources, form windows exclude the target GW's own matches, upcoming blank/double counts, odds as-of excludes closing odds and post-deadline snapshots.

Commit: `feat(features): baseline feature builders`.

### Task 4: Corrupt-the-future harness, architecture test, CLI

**Files:** `src/fplopt/features/leakcheck.py`, `tests/test_leakcheck.py`, `tests/test_features_architecture.py`, `src/fplopt/cli.py`, `tests/test_cli.py`.

- `corrupt_future(tables, deadline, seed) -> dict[str, DataFrame]`: for every table, rows with `available_at >= deadline` get every column except `available_at` replaced with random values of the same dtype (numbers, strings, timestamps, booleans, nullable types; keys too); additionally append a copy of N random past rows with `available_at` moved after the deadline and their values scrambled (catches code that dedups/sorts before filtering). Never touch rows with `available_at < deadline`.
- `feature_fingerprint(features) -> dict[name, str]`: sha256 over a canonical serialisation (column names, dtypes, values in order; Parquet bytes via pyarrow with fixed settings are fine).
- `check_leakage(store_tables, deadlines, seed) -> list[Leak]`: for each deadline compute features on the clean tables, on a corrupted copy, and on a *truncated* copy (future rows deleted); all three fingerprints must match. Report per feature/deadline.
- Tests: (a) a deliberately leaky builder (e.g. one that reads `player_match` unfiltered via a back door in the test, or uses `max(event_time)` over an unfiltered frame passed in) is detected; (b) all `FEATURES` pass on the synthetic world at ≥ 3 deadlines (CI); (c) `@pytest.mark.realdata` test: if `data/` exists, run on ~10 real deadlines spread over 2016/17–2024/25 and 2026/27 (skip 2025/26) — skipped in CI. Register the marker in pyproject.
- Architecture test: AST-scan every module in `src/fplopt/features/` except `store.py` and `leakcheck.py`: no imports of `pyarrow`, `duckdb`, `fplopt.build`, `fplopt.ingest`, `pathlib`/`open`, and no `pd.read_*` calls. Feature builders must take exactly one parameter (the view).
- CLI: `fplopt check leakage [--deadlines N] [--seed S]` runs `check_leakage` on `data/` at N deadlines (default 12) sampled deterministically from `gameweek` (excluding 2025/26), fails (exit 1, alert) on any leak, logs a summary.

Commit: `feat(features): corrupt-the-future leakage harness and checks`.
