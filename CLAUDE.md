## Commands

- `uv sync --all-extras` — install everything
- `uv run pytest` — tests
- `uv run ruff check . && uv run ruff format .` — lint/format
- Rust port (`crates/`, plan `docs/superpowers/plans/2026-10-28-rust-migration.md`; binary `fplopt-rs`, same subcommands and flags as `fplopt` for what's ported): `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo fmt --all`. Golden files for Rust tests: `tests/fixtures/rust_golden/`, regenerated by `uv run python tests/test_rust_golden.py`
- `cargo run --release -p fplopt-cli -- check parity table --python A.parquet --rust B.parquet --keys k1,k2 [--rtol 1e-9 --atol 0] [--out DIR]` — the migration's parity gate on one table: rows matched on the keys, schema/rows/values diffed (floats within tolerance, null ≠ NaN), `report.json` in `results/parity/`, logged to `results/experiments.csv` (family `rust parity`); exit 1 on any difference
- `uv run fplopt snapshot daily|tick` / `uv run fplopt backfill element-summary` — archiver jobs (see `deploy/README.md`)
- `uv run fplopt check freshness [--max-age-hours 36]` — fails (and alerts) if the newest bootstrap snapshot is missing or too old
- `uv run fplopt backfill football-data|vaastav|fplcache|espn` — one-off historical backfills into `raw/` (run on the server, see `deploy/README.md`); `espn`: PL, cup and European match summaries of PL clubs from 2016/17 (~2–3 h, resumable; `snapshot daily` keeps it current)
- `uv run fplopt rules export <season>` (e.g. `2026-27`, `--out` default `config/scoring`) — rules config from an archived bootstrap
- `uv run fplopt check leakage [--deadlines 12]` — corrupt-the-future check of every feature, xP model (`model:*`) and decision probe (`probe:*`) on real `data/` at a fixed edge list (every season's GW1, 2019/20 GW39/GW47, 2021/22 GW18, 2022/23 GW8, first deadline with snapshots, the live deadline) plus N random deadlines (~23 min with `model:v1`); `uv run pytest -m realdata` runs the same edges plus 10 fixed deadlines (~20 min; plain `pytest` skips it)
- `uv run fplopt build all` (or `build <table>`) — rebuild `data/*.parquet` from `raw/` (~1.5 min; needs a local `raw/` copy, see `deploy/README.md`). Club names across sources live in `config/teams.csv`; Understat mapping overrides in `config/overrides.csv`.
- `uv run fplopt backtest run --seasons 2016-2024 [--policy greedy|roll] [--xp rolling|ep_next|ep_next_fade] [--threshold 1.0 --horizon 6 --decay 0.85 --max-transfers 1] [--spec optimizer:ep_next] [--starts "template@1,random:5@1,random:3@20"] [--jobs N] [--family NAME] [--out results/<name>]` — replay one policy (or any `--spec`) over seasons × start states (~1.5 min for that grid with greedy); writes `gws.parquet` + `summary.json`, prints season totals by start GW with captain/XI regret and the predicted-vs-realized transfer gain (optimizer's curse slope)
- `uv run fplopt backtest compare --a greedy:ep_next --b greedy:rolling --seasons 2021-2024 [--continuation roll:rolling|own --reference b|a --k 4 --stride 4] [--no-per-decision] [--block-length 4 --n-boot 2000 --seed 0] [--family NAME]` — paired comparison of two policy specs (`name:xp[:key=value,...]`, e.g. `greedy:rolling:threshold=2.0`, `optimizer:ep_next_fade:max_hits=1,hit_margin=2,chips=1`; optimizer keys `horizon`, `decay`, `hit_margin`, `max_hits` (int or `none`), `itb_value`, `bench_from_minutes` (0/1; default 1: per-GW bench weights from the xP frame's `p_play`, i.e. `v1`; baseline models keep the fixed weights), `min_minutes` (expected-minutes floor for non-owned candidates, default 180 over a full horizon, pro rata on a shorter one; frames with `e_minutes` only), `chips` (0/1); defaults = `OptimizerParams()`, no chips): full-run and per-decision (non-overlapping k-GW windows) differences with GW-block bootstrap 80% CIs (lower bound = one-sided α 0.10), realized and xG-scored, each for all seasons and split into develop (2016/17–2022/23) / validate (2023/24–2024/25), with a one-sided season-level t-test p and the mean deflated for the comparison family's variants (mean − SE·√(2 ln N); `--family`, default `<B spec> <seasons>`; `n_variants` in the log counts the family's runs). `--continuation own`: each arm continues with its own policy and xP after the decision; `--reference a`: decision states from A's own run (optimizer vs greedy with own continuation: 14–17 min for 2016–2024 × 4 starts at `--jobs 14`; ~3 min for greedy vs roll on 2016–2024 × 6 starts; optimizer vs greedy 8–15 min for 2021–2024 / 15–20 min for 2016–2024 × 6 starts at `--jobs 14`, chips ~35 min for 2021–2024 × 4 starts without per-decision). `--jobs N` (default CPUs − 1) runs the (season, start) units in N processes, same results as `--jobs 1`. Seasons: `2016-2024`, `2021,2023`, `2021-22` or mixed; the holdout season, `ep_next`/`ep_next_fade` before 2021/22 and seasons without data are refused (exit 2). Both commands append to `results/experiments.csv` (tracked; the rest of `results/` is gitignored)
- `uv run fplopt models eval --models v1,rolling,ep_next --seasons 2016-2024 [--jobs N] [--n-random 3] [--out results/<name>] [--family NAME]` — walk-forward xP evaluation (`fplopt.evaluate`, Phase 5 criterion 1) at every deadline: MSE per player-GW by horizon and predicted-xP band, candidate MSE (optimizer top-N union), MAE (diagnostic), captain/XI regret on the template + N random squads, pairwise one-sided Diebold-Mariano tests clustered by GW, per split (develop/validate); `ep_next`/`ep_next_fade` run from 2021/22 only (earlier seasons skipped for them). Writes `predictions.parquet`, `regrets.parquet`, `metrics.json`; appends to `results/experiments.csv` (~65 s for rolling + ep_next + ep_next_fade on 2016–2022 at `--jobs 7`)
- `uv run fplopt optimize plan --season 2024 --gw 10 [--start template|random:SEED | --entry TEAM_ID [--squad-file squad.toml]] [--xp ep_next|ep_next_fade|rolling|v1] [--chips/--no-chips] [--max-hits N|none] [--hit-margin M] [--horizon 6] [--decay D] [--top-k 3]` — the top plans and the roll plan (per GW transfers by name, captain/vice, chip, xP, hits, bank, FTs; gain vs roll) and plan #1's lineup, from a template, random or real squad at a real deadline. `--entry` imports an FPL team (squad, purchase prices, bank, free transfers, chips) from FPL's public API (`fplopt.entry`); `--squad-file` (TOML) overrides any of it, or gives the whole squad without `--entry`. `uv run fplopt optimize squad --season 2026 --gw 6 --entry TEAM_ID [--out squad.toml]` writes the import as a squad file to check or edit (seconds without chips, ~15 s with; a 60 s wall-clock cap per solve here and in `optimize bench` only — backtests use the deterministic node limit, `OptimizerParams.node_limit`)
- Chip study (`docs/superpowers/plans/2026-10-11-chip-policy.md`):
  - specs `chipgains:v1:<optimizer keys>` (S0 plus per-GW chip gains in the GW rows), `chiprules:v1:<optimizer keys>,t_tc=,t_bb=,k_fh=,t_wc=` (rule baseline H) and `optimizer:v1:...,chips=1,chip_shrink=k` (estimated terminal values from `config/chips/terminal-values.json` × k);
  - `uv run fplopt chips values --gains results/<chipgains run> [--out config/chips/terminal-values.json]` estimates that table, develop seasons only;
  - `backtest compare` also reports the full-run window t-test on 8-GW cells, the chip study's statistic.
- `uv run fplopt holdout check` — the 2025/26 inputs (player pool, `ep_next`, clubs without players) at every deadline, no results read; fails on any gap. `uv run fplopt holdout run [--jobs N] [--out results/phase6-holdout]` — **the** pre-registered Phase 6 run (PLAN §9 *Phase 6 design*, settings fixed in `fplopt.backtest.holdout`): system vs both baselines and the fallback, the gate and the go-live verdict; logged (family `phase6 holdout`) before printing. Runs once: refuses if the experiment log already holds it, if the checkout has uncommitted changes or HEAD isn't the commit tagged `phase6-holdout`, or if `--out` isn't empty
- `uv run fplopt live prepare` — rebuild `data/` (`build all` in a subprocess) and the **plan context** for the next deadline now: v1 xP, pool, players and past deadline prices in `state/context/<id>/` (`fplopt.bot.context`; ~4 min on botbox). `uv run fplopt live tick` — the 15-minute alert job (`fplopt-live.timer`, `fplopt.bot.live`): rebuilds the context when the archive, code or deadline changed; sends the recommendation 24 h before each deadline (after a fresh FPL snapshot); re-runs after the pre-deadline snapshot and messages only on a change. `uv run fplopt bot run` — the Telegram bot (`fplopt-bot.service`, long polling; `fplopt.bot.app` over `fplopt.bot.service`): invite-only, `/register`, `/plan`, `/chips` (the chip planner's search, information only), `/transfer` (moves already made for the coming GW, which FPL hides until the deadline), `/setft`, `/alerts`; every plan uses FPL's live prices (`context.with_live_prices`, fetched at most every 5 min); user state in `state/bot.sqlite` (`FPLOPT_STATE_DIR`). Plans use `holdout.SYSTEM`'s settings (`fplopt.bot.planner.LIVE_PARAMS`), no chips
- `uv run fplopt optimize bench [--deadlines 10] [--seed 0] [--all-chips K] [--no-prune-study] [--seasons 2021-2024,2026] [--xp ep_next,rolling] [--floors 0,30,60,90,135,180]` — optimizer benchmark (#10) on real deadlines (default 2021/22–2024/25 + 2026/27; template/random starts × the `--xp` models): no-chip / top-3 / chip-search times and gaps, pruning variants' objective loss, and for `v1` the expected-minutes floors' loss vs no floor and the no-chip solve with the fixed bench weights; writes `cases.csv`, `prune.csv`, `summary.json` to `results/<UTC>-bench` (~1–2 h for 10 deadlines; `--all-chips K` adds the exhaustive chip search on K cases, 2–50 min each)

## Invariants (do not break)

- `raw/` is append-only, never edited. Every file is compressed (`.json.gz`, `.csv.gz`; fplcache `.json.xz` copied verbatim) with a timestamp in the path.
- Derived tables are rebuilt from `raw/`; never hand-patch Parquet.
- Every derived row has `event_time` and `available_at`. Feature builders and the backtester read only through `DataStore(data_dir).as_of(deadline)` (keeps `available_at < deadline`); feature builders take exactly one argument, the view. Nothing else in `fplopt.features` reads files (enforced by `tests/test_features_architecture.py`). Table kinds and keys live in `fplopt.build.tables.TABLES`.
- Never key on FPL player ids (they reset each season); use `player_key` from `player_dim`.
- Each data source sits behind an adapter in `src/fplopt/adapters/`.
- User state goes in SQLite (not DuckDB — the bot and pipeline would both write).
- Everything user-facing is keyed by `user_id`.

## Conventions

- Notebooks: flat, copy-pasteable cells; anything reused moves into `src/fplopt/`.
- Tune on component metrics (log loss, calibration, RMSE), not season totals.
- Don't touch the 2025/26 holdout season until Phase 6.
